In this Everyday we will simulate the following scenario:
"It's Election Night and you're in charge of Election Integrity.
Over the next couple of hours, hundreds of thousands of voting __ballots__ will
be entered in voting machines. Each ballot has a unique random number REF.

Let's sit down and write a small program with the following requirements:
1. Our program should be able to handle a stream of up to 100,000 random numbers 
arriving via TCP/IP over a period of one (1) second.
2. One program will be in charge of generating random numbers and streaming them.
3. We will store all numbers in a database, in our case ScyllaDB.

# Rust
We will need to install Rust and also a database drive for the database technology
that we intend to use, ScylllaDB. For this we use the [scylla-crate](https://crates.io/crates/scylla) REF.

# Database: ScyllaDB
We can choose to run our database either locally or remotely.
In our case we will choose to run it remotely in case our local site becomes a target
of election interference ops.
We'll use the ScyllaDB installation guide for your our operatingsystem (MacOS).

# Server
This server will stream random numbers, in real time, to any client subscribing to it.
Once logged in, the client can set a few parameters that will affect the stream, 
such as size of the numbers and the average frequency per second (including an upper and lower bound)
of the stream.

# Client
The client will process the stream of numbers. Once the size of the process numbers
has surpassed a threshold (set by the user) the client will indicate (with a guage)
if the stream is staying inside bounds that are expected by Benford's Law.
If the stream of numbers starts moving outside of Benford bounds, the client will
issue an alert (the user can set how far outside of the bounds, or how long bounds have to be crossed, for the alarm to be issued).

# Example: Michigan Ballots
In the state of Michigan, US, each voting ballot is assigned a unique random number.
This is done to ensure the integrity of the election process. 

## System Design
1. __Random Number Generation__  
Source of Randomness: The random numbers for ballots are typically generated using a secure random number generator (RNG).
It is important that the algorithm employed by the RNG (be it software-based or hardware-based) adheres to the US national standards for randomness and cryptographic security.
2. __Interval and Range of Numbers__  
Interval: The random numbers assigned to ballots are usually within a specific range that allows for a sufficient number of unique identifiers. The range can vary based on the total number of ballots printed for a particular election or precinct.
Uniform Distribution: The goal is to have a uniform distribution of these numbers across the possible range to minimize predictability and ensure fairness.
3. Length of the Random Number
In Michigan, the random number assigned to each ballot typically consist of 6 digits. 
This allows for a range of numbers from 000000 to 999999, resulting in a total of 1,000,000 possible combinations.
4. Process of Assignment
Ballot Preparation: During the ballot preparation phase, the election officials will generate the random numbers for the ballots and assign them before printing.
Tracking: Each ballot is marked with its unique random number, allowing election officials to track the ballots throughout the election process. This is crucial for verifying the integrity of the election.
5. Transparency and Security
Audit Trails: The use of random numbers allows for a verifiable audit trail, which can help detect any irregularities in the election process.
Security Measures: The entire process of generating and assigning random numbers is typically governed by strict security protocols to prevent tampering and ensure the integrity of the electoral process.

## Step 4: Server _ Generate Random Number and Send it
In generating random numbers we want to make sure that werwer are adhering to the
the US national standard fro generating random cryptographcly secure random numbers.

```rust
use rand::Rng;
use scylla::{Session, SessionBuilder};
use std::sync::{Arc, Mutex};
use tokio::time::{sleep, Duration};
use uuid::Uuid;

#[tokio::main]
async fn main() {
  // Create a ScyllaDB session
    let contact_points = "127.0.0.1:9042"; // Adjust if needed
    let session: Session = SessionBuilder::new()
        .known_node(contact_points)
        .build()
        .await
        .expect("Failed to connect to ScyllaDB");

    // Arc and Mutex to share the session across threads
    let session = Arc::new(Mutex::new(session));

    // Generate and insert random numbers
    let number_of_values = 100_000;
    let mut handles = Vec::new();

    for _ in 0..number_of_values {
        let session_clone = Arc::clone(&session);
        handles.push(tokio::spawn(async move {
            let value: i32 = rand::thread_rng().gen_range(0..100);
            let id = Uuid::new_v4();

            let session = session_clone.lock().unwrap();
            session
                .query("INSERT INTO random_numbers_keyspace.numbers (id, value) VALUES (?, ?)", (id, value))
                .await
                .expect("Failed to insert value into ScyllaDB");
        }));
    }

    // Wait for all insertions to complete
    for handle in handles {
      handle.await.expect("Task failed");
    }

    println!("Inserted {} random numbers into ScyllaDB.", number_of_values);
}
```
