## States Machines to the rescue
Let's model this using the TypeState Pattern. Let's list what we want to model:
1. Methods on an object are only available when the object is in certain states.
2. We want a way of encoding these states at the type level, such that attempts to use 
    the methods in the wrong state will fail the program to !!compile!!.
3. We want State transition methods that change the type-level state of objects, 
    such that the methods in the previous state are no longer possible in the new state.

## State

```scala
impl Wizard<Rested> {
    fn cast_spell(self) -> Wizard<Tired> {
        println!("The rested Wizard, {}, cast a spell and is now tired.", self.name);
        Wizard {
            name: self.name,
            _state: marker::PhantomData,
        }
    }
}

impl Wizard<Tired> {
    fn go_to_sleep(self) -> Wizard<Sleeping> {
        println!("The tired Wizard, {}, went to sleep.", self.name);
        Wizard {
            name: self.name,
            _state: marker::PhantomData,
        }
    }
}

impl Wizard<Sleeping> {
    fn wakeup(self) -> Wizard<Rested> {
        println!("The Wizard, {}, woke up from sleeping and is now rested.", self.name);
        Wizard {
            name: self.name,
            _state: marker::PhantomData,
        }
    }
}
```
## Main function

```scala
fn main() {
    let gandalf = Wizard::new(String::from("Gandalf")); // new state:Wizard<Rested>
    let gandalf = gandalf.cast_spell(); //  new state: Wizard<Tired>
    
    //  won't compile because cast_spell isn't available when the object is in state tired.
    let gandalf = gandalf.cast_spell(); 
    
    let gandalf = gandalf.go_to_sleep(); //  new state: Wizard<Sleeping>
    let gandalf = gandalf.wakeup(); //  new state: Wizard<Rested>
}
```
