## ConcernsMotivation

There are a number of reasons to be careful when vibe coding on a VPS:

1. __Security:__ - the Ai might execute malicious code and delete valuable data on the server.
2. __YOLO:__ - continously accepting the AI's suggested
changes can get tedious, but auto-accepting changes (like Claud's --dangerously-skip-permissions) is also risky.
3. __Permission:__ - some of the operations that the Ai want to use requires `root` access, which poses a risk.
4. __State Handling:__ - Claude Code is stateful which might be problematic if we concurrently access our server from different devices without resetting state.
5. __Sharing:__ - If multiple devs are working on the same project-claude state, that may cause an issue.
6. __Internet Access:__ - the Ai usually needs Internet access, so who provides that during long running processes? We want a Ai-coding environment which does not get interrupted due to Wifi disconnets.

## Requirements

We want our Ai VPS setup to meet the following requirements:

1. __Hands-free:__ For a React webapp with a Python FastAPI backend, we want our AI to iterate without our commitment.
2. __Debug:__ - we want to be able to debug our webapp using `Chrome` with the `Debug MCP` repo.
3. __Persistence:__ - Our webapp's backend needs to be able to talk to Supabase
4. __Claude:__ - able to run Claude Code.
5. __Cheap:__ - cheap is always nice.
6. __Easy to setup and use:__ - the Ai VPS needs to be easy to install, maintain, secure (Firewall).
7. __Secure:__ - we have to be able to trust our Ai VPS, given that we might be dealing with sensitive data.

## Hardware
Based on our requirements, we can set the following hardware requirements:

1. 2 Cores + 8 GB of ram with SSD as minimum hardware reqs.
2. Low latency (< 50ms) to the area I live in on peak times (NYC Area)
3. Less than $20 a month (you can buy a reasonable jump box for $120)
4. Linux on x86 (some things still don’t run great on ARM)
5. A provider that is considered stable and reliable.

### Setup and installations on the VPS
For good practice, do the following:

+ Create a personal account with sudo, rather than maintaining the machine using `root`.
+ Install the usuall Linux machine suspects: git, Xfce, etc.
+ Rather than installing using the Chrome Linux `.deb`, try going the repo route.
+ Make a shortcut to run Chome with the following params to enable your MCP to safely connect

```bash
        --remote-debugging-port=9222
        --remote-debugging-address=127.0.0.1
        --user-data-dir=/home/<user>/.chrome_dev_profile
```

+ Install the latest stable version of Node.js (try nodesource)
+ Install Python (sudo add-apt-repository ppa:deadsnakes/ppa)
+ Install uv (use pipx to install uv)
+ Install Claude Code (npm install -g @anthropic-ai/claude-code)
+ Install VSCode (add the Microsoft repo to apt)
+ Install the VSCode plugins for Claude Code
+ Install cline (with Claude Code selected for AI provider)

## MCP
https://github.com/benjaminr/chrome-devtools-mcp
For Chrome MCP I used `benjaminr/chrome-devtools-mcp`, with the following Linux build instructions:

+ Download the repo
+ Make an environment and install the dependencies with uv, make sure to make the environment
+ Set up the MCP to run it with the `—project` flag via uv in the repo directory (I’ll show my example below)
++ MAKE SURE YOU HAVE A FORWARD SLASH AT THE END OF YOUR PROJECT PATH.
+ At first I struggled with the “claude mcp” via the command line but it was much easier to just edit the .claude.json file in my home directory.
++  Args should all be broken out (see below, Claude Code is super picky about this config)

The other I set up was supabase, but because it’s not running locally this was a snap. You can see the mcp part of my `~/.claude.json` here:

```
`// ~/.claude.json
  "mcpServers": {
    "chrome-devtools": {
      "type": "stdio",
      "command": "uv",
      "args": [
        "run",
        "--project",
        "/home/rick/Claude/chrome-devtools-mcp/",
        "/home/rick/Claude/chrome-devtools-mcp/server.py"
      ],
      "env": {
        "CHROME_DEBUG_PORT": "9222"
      }
    },
    "supabase": {
      "command": "npx",
      "args": [
        "-y",
        "@supabase/mcp-server-supabase@latest",
        "--read-only",
        "--project-ref=<put project ref here>"
      ],
      "env": {
        "SUPABASE_ACCESS_TOKEN": "<put token here>"
      }
    }
```
set up your own Vibe VPS.
