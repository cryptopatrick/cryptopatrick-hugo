## Workflow vs Agents
A Workflow is a predefined (rigid) fixed sequence of steps - think Voice Information Systems "Press 1 to...".
In contrast, an agent 'acts' dynamically by reasoning and using memory. Rigid workflows are reliable but are less able to adapt to handle different situations.

## ReAct Pattern
+ Act: let the LLM call a specific tool
+ Observe: pass the tool output back to the LLM
+ Reason: let the LLM reason about the tool output to decide what to do next.

## (Information) State Update Theory in RAG/MCP/AZR?
The shared memory or object tracking the current status of the agent's tasks. This way the agents always knows what has happened (history) and what information it has gathered.
An agent can be seen as a graph, consisting of _nodes_ and _edges_. The flow is cyclic until the agent reaches an end state. Work happens in nodes.

Each node receives the current state, does some action and might 
update the state, and then passes the state to the next node.
Edges are used to connect nodes with each other, creating sequences of operations. Some edges are unidirectional,
but some edges are state-conditional, where the next node 
is selected based on the current state.



## Tools
These are used to perform _actions_. They might be a database
call, a web search, a computation, etc. The output from a tool
is usually fed into the current state, updating it.
