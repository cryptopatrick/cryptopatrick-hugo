## Engineering a Parallelization-resistant puzzle

> __Insight__: A human pregnancy (normally) takes 9 months. The process cannot be parallelized by two women having a baby in 4.5 months.

In order to reduce the hardware advantage that an attacker might exploit by mounting a massively parallelized attack to break our encryption, we want a process that is very hard to parallelize.

{{<indentline>}} The idea is simple: we want to send information into the future. More precisley, our aim is to encrypt a message so that it cannot be
decrypted by anyone, until an (approximte) amount of time into the future.

In a paper published in 1996, cryptologists Rivest, Shamir, and Wagner suggested the following solution: encrypt a message to such degree that it is unlikely to be decrypted until a pre-determined amount of time has passed.  

Decrypting the message boils down to solving a cryptographic __puzzle__: namely, the classic RSA (Rivest-Shamir-Adelmann); security by requiring factorization of a large prime. 

> __Clarification:__ It's important to note that with __future__ we really mean __after a computer has continuously worked on the puzzle for an approximate amount of time__. So "two years in the future" means "a computer working on trying to decrypt the message for 24 hours each day, over a period of __approximately__ two years.".

### The Challenge

{{< figure src="/img/time-lock-message/ilmari-kumpunen-cursedchest-rebound.jpg">}}  

We have to vastly different qualities, _real time_ and _CPU time_. How can we 
make them agree as closely as possible?

The main problem is that while _real time_ flow does not vary (unless we're affected
by time dilation due to proximity to a black hole), CPU time (the number of cycles
that the CPU can spin in 1 millisecond) has been increasing ever since computers
were invented. This essentially means that if Alice's computer has 2x
the CPU speed of Bob's computer, then she could theoretically solve the puzzle
twice as fast. 

> The rise of parallell chips is the greatest difference maker in comparing the speed of one computer to the next. 


This means that we need a solution which, to the greatest extent, reduces the
benefits of parallell computers. Our time-lock puzzle need to have have these two properties:
1) it's intrinsically sequential - just as "two women can't have a baby in 4.5 months", our puzzle should drastically reduce the  the benefit of parallell computers
2) large investment in hardware won't really be a benefit either 

> The proposed time-lock puzzle will only "lock" for an _approciximate_ amount of time since computers speed still vary.

Suppose that we want to create a 100-digit prime number.  
__The Prime Number Theorem__ <enter link or footnote> states that the _density_
of primes near a large number is _approximately_ $1/\mathbb{ln}\\,x$.
In other words, the probability of a 100-digit number is prime is:
$$\frac{1}{\mathbb{ln}(10^{100})} \approx \frac{1}{230}$$


Knowing there are no even primes above 2, we can limit our search to only odd numbers. That improves $\approx \frac{1}{230}$ into $\approx \frac{1}{115}$, essentially doubling our chances of finding a prime number.

Expecting to find a lot more _composite numbers_ (numbers that are _not_ prime),
it would be helpful if we could quickly determine if a number is composite or not.
The famous __Fermat's Theorem__ comes to our rescue.

__Fermat's Primality Test__: Let $n>1$ be an odd integer.  Choose an integer $b$ 
with $1<b<n$, often we simply choose $b=2$. If $b^{n-1} \not\equiv 1 \\, (\mathbb{mod} \\; n)$ then $n$ is composite.

> The theorem can be stated the opposite way: _if there exist solutions to $x^2 \equiv 1 (\mathbb{mod} \\; n)$ other than $\pm 1$, then $n$ is not a prime number.

A _time-lock puzzle_ is a computational puzzle that requires a precise amount of
time to solve. The solution to the puzzle is the _key_ that can be used to _decrypt_
the encrypted information. 

The solution is based on _repeated squaring_. 
Suppose Alice has a message $M$ that she wants to encrypt with a time-lock puzzle for a period of $T$ seconds:

> The security of the _RSA encryption scheme_ relies on the fact that it's much harder to factorize $n$ into $p$ and $q$, than to produce $n$ by multiplying $p$ and $q$. In other words, there is an asymmetric relation ship between the two operations.

### Step 6/7
Alice `chooses` a _random modulo_ $a$ with ($1<a<n$), and `encrypts` $K$ as
$$C_K = K + a^{2^t}\quad (mod\\; n)$$  

To do this she first `computes`:
$$e=2^t\quad (mod\\; \phi(n))$$

and then `computes` $b$, the _solution_ to the puzzle:
$$b=a^e \quad (mod\\; n)$$


### Step 7/7
Finally, Alice produces the _time-lock puzzle_ $(n,a,t,C_K,C_M), and ereases
the variables, $p$ and $q$, that were used during the production of the puzzle.


## Solving the puzzle
Assuming the bitlength of the chosen encryptpion scheme used is large enough, simply
brute force searching for the solution to the puzzle (finding the key $K$
to the selected encryption $ENC$) is _infeasable_.

The fastest way to solve the time-lock puzzle is to determine:
$$b=a^{2^t}\quad (mod\\; n)$$ . 

Knowing $\phi(n)$ enables $2^t$ to be `reduced` efficiently to $e\quad (mod\\; n)$, 
so that $b$ can be computed using #Step 7/7.

# The Source Code

```rust
use num_bigint::BigUint;
use num_traits::{One, Zero};
use rand::Rng;
use std::ops::{Mul, Sub};

fn generate_large_prime(bits: usize) -> BigUint {
    loop {
        let mut rng = rand::thread_rng();
        let prime_candidate = rng.gen_biguint(bits);
        
        if is_prime(&prime_candidate) {
            return prime_candidate;
        }
    }
}

// A simple primality test (not efficient for large primes)
fn is_prime(n: &BigUint) -> bool {
    if n == &BigUint::one() || n == &BigUint::from(2u32) {
        return true;
    }
    
    let two = BigUint::from(2u32);
    let mut d = n.sub(&BigUint::one());
    
    while d.clone().rem(&two).is_zero() {
        d = d.div(&two);
    }

    for _ in 0..5 {
        let a = rand::thread_rng().gen_biguint_range(&BigUint::from(2u32), n);
        let mut x = a.modpow(&d, n);
        
        if x == BigUint::one() || x == n.sub(&BigUint::one()) {
            continue;
        }
        
        while d != n.sub(&BigUint::one()) && x != n.sub(&BigUint::one()) && x != BigUint::one() {
            x = x.modpow(&two, n);
            d = d.mul(&two);
        }
        
        if x != n.sub(&BigUint::one()) {
            return false;
        }
    }
    
    true
}

fn rsa_keygen(bits: usize) -> (BigUint, BigUint, BigUint) {
    let p = generate_large_prime(bits);
    let q = generate_large_prime(bits);
    let n = &p * &q;
    let phi_n = (p - 1u32) * (q - 1u32);
    
    (p, q, phi_n)
}

fn main() {
    let bits = 512; // Number of bits for the primes
    let (p, q, phi_n) = rsa_keygen(bits);

    println!("Prime p: {}", p);
    println!("Prime q: {}", q);
    println!("n = p * q: {}", &p * &q);
    println!("phi(n) = (p-1)(q-1): {}", phi_n);
}
```
