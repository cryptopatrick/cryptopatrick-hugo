## Image Space
The first concept we'll look at is what we'll call _image space_, the space of all possible images. In this post I'll use a square with the arbitrary size of _1024*1024 pixels_, but you can use whatever you like. This gives us an image space of $1024^2$, or 
1_048_576 pixels.

If we have two pixels and align them orthogonally, then we end up with a traditional cartesion grid, with the value of pixel 1 in one direction (let's say horizontal x), and the pixel 2 in a peripendicular direction (let's say vertical y), for an $R^2$ space.
However, in our case, we'll let each of our 1 million pixels represent and axis in our image space, giving us an $R^{1_048_576}$ hypercube image space.

> A _hyper cube_ is a geometrical figure in $R^{4+}$ (four or more) dimensions,  which is analogous to a cube in three dimensions.

## Values
Each pixel can take a value from $0$ up to $255$, from black to white and covering color  for a total range of $256$ values.
Because RGB uses an 8 bit byte to store color for each channel; 8 bits for Red, 8 for Green, and 8 for Blue. This gives 24 total bits to store color information.

Within the 8 bits for each channel, you can represent 256 colors.
So far, so good. Buy why is 255 the maximum value?



Pixel values represent the color and brightness of each individual pixel in an image. In grayscale images, a single pixel value (ranging from 0 to 255) represents brightness, with 0 being black and 255 being white. For color images, pixels are usually represented by three values (R, G, B), each representing the intensity of red, green, and blue respectively, within the same 0-255 range
